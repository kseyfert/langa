# Модуль «Задания»: модель данных и воркфлоу

Часть тренажёра грамматики (см. `architecture.md`). Модуль генерирует задание по юниту и типу, принимает ответы, проверяет их и записывает всё в лог. API, структуру кода и интерфейс проектирует реализация; здесь — что хранится, как устроены задание и оценка и как проходит одно задание от начала до конца.

Эталон логики, промптов и интерфейса — прототип `grammar-drill.html` (артефакт). Каталог юнитов — таблица `units` (см. `catalog-spec.md`).

## 1. Границы модуля

**Входит:**
- генерация задания по `(unit_id, type)`;
- приём ответа и проверка: gap/choice локально, остальные типы через Claude;
- повторные попытки после «верно, но без целевой конструкции», кнопка «Показать разбор»;
- лог: каждое задание и каждая попытка сохраняются в базе.

**Не входит:**
- выбор юнита и типа (пока выбирает пользователь вручную, потом — планировщик);
- рейтинг юнитов (модель ученика читает лог этого модуля);
- таймер сессии;
- оспаривание проверки — будет отдельной фичей позже.

## 2. Понятия

| Понятие | Что это |
|---|---|
| **Задание** (`exercise`) | одно сгенерированное упражнение по одному юниту одного типа и всё, что с ним происходило. Одна строка в `exercises` |
| **Попытка** (`attempt`) | один отправленный ответ на задание и его оценка. У открытых типов попыток может быть несколько (повторные после «без целевой конструкции»), у gap/choice — одна |
| **Оценка** (`evaluation`) | результат проверки одной попытки: вердикт, целевой юнит, побочные юниты, исправления |
| **Статус задания** | `accepted` — последняя попытка верна с целевой конструкцией, `failed` — последняя попытка неверна, `null` — ни того ни другого (в процессе, только ответы без целевой конструкции, пропущено). Статус — для просмотра; рейтинг считается по оценкам попыток |

## 3. Типы заданий и их содержимое

Пять типов: `gap`, `choice`, `rephrase`, `translate`, `free`. Содержимое задания (`exercises.content`) зависит от типа. Поля `*_ru` — по-русски.

```ts
type GapContent = {
  instructions_ru: string;
  items: { text: string;          // одно предложение с одним пропуском "___", база в скобках после пропуска: "She ___ (work) here."
           answers: string[];     // все допустимые варианты, включая сокращённые и полные формы
           explain_ru: string }[];// 6 пунктов
  focus?: string[];               // план: пункт «Употребления» guide на каждый items[i] (раздел 7); клиенту не уходит
};

type ChoiceContent = {
  instructions_ru: string;
  items: { text: string;          // предложение с пропуском "___"
           options: string[];     // 2–3 варианта
           correct: number;       // индекс верного
           explain_ru: string }[];// 6 пунктов
  focus?: string[];               // как у GapContent
};

type TranslateContent = {
  instructions_ru: string;
  source_ru: string;              // 1–3 связанных предложения, перевод которых требует целевой конструкции
  target_note_ru: string;         // что заметить; показывается только после разбора
  reference_en: string[];         // генерируется один эталон
  focus?: string[];               // как у RephraseContent
};

type RephraseContent = {
  instructions_ru: string;
  source_en: string;              // предложение без целевой конструкции; её самый естественный пересказ — с ней
  reference_en: string[];         // генерируется один эталон; в старых заданиях бывает до трёх, показывается первый
  focus?: string[];               // один пункт «Употребления», на который составлено задание; клиенту не уходит
  start_with?: string;            // только в старых заданиях (до rephrase-gen-v3), не генерируется и не показывается
};

type FreeContent = {
  instructions_ru: string;
  prompt_ru: string;              // ситуация или вопрос
  prompt_en: string;              // то же по-английски
  reference_en: string[];         // пример ответа
};
```

Содержимое валидируется при генерации (как `normalizeEx` в прототипе): пункты с неверным форматом отбрасываются, задание без единого валидного пункта считается ошибкой генерации.

## 4. Оценка попытки

### 4.1. Открытые типы (rephrase, translate, free)

Проверяет Claude. Формат ответа модели:

```ts
type OpenEvaluation = {
  verdict: "correct_target" | "correct_non_target" | "incorrect";
  summary_ru: string;
  target: {
    status: "correct" | "error" | "partial" | "not_used";
    score: number | null;            // 0–100; null при not_used
    fragment: string;                // точная цитата из ответа или ""
    fix: string;                     // исправленный фрагмент или ""
    comment_ru: string;
  };
  others: {                          // ВСЕ прочие юниты каталога, задействованные в ответе
    unit_id: number;                 // id из таблицы units
    status: "correct" | "error" | "partial";
    score: number;                   // 0–100
    notable: boolean;                // верное и продвинутое/особенно удачное употребление
    fragment: string;
    fix: string;
    comment_ru: string;
  }[];
  issues: {                          // ошибки вне каталога: орфография, лексика, смысл
    fragment: string; fix: string; comment_ru: string;
  }[];
  corrected_answer: string;          // ответ с минимальными исправлениями
  natural_version: string;           // как сказал бы носитель
};
```

Правила вердикта:
- `correct_target` — грамматически верно, отвечает на задание, целевая конструкция использована верно.
- `correct_non_target` — грамматически верно и отвечает на задание, но целевая конструкция обойдена допустимым способом (например, going to вместо present continuous для договорённости). Это не ошибка.
- `incorrect` — есть ошибки: грамматические, смысловые или неверный выбор конструкции для ситуации.

Кому засчитывается ошибка:
- **Неграмотный ответ:** ошибка засчитывается тем юнитам, к которым она относится — целевому и/или побочным. Если целевая конструкция не использована, а в ответе есть ошибки, у целевого юнита `status = not_used`, и модель ученика считает это провалом по целевому юниту.
- **Грамматически верный, но неверный по смыслу выбор конструкции** (спросили, что вы делаете сейчас, а вы грамотно ответили про завтра) — это ошибка **целевого юнита**: `target.status = error`, низкий `score`, вердикт `incorrect`. Не `correct_non_target` и не `issues`.
- **Ошибки вне каталога** (орфография, лексика, не связанный с грамматикой смысл) — в `issues`, на юниты не влияют.

Шкала баллов: 100 — безупречно; 80–95 — верно, но немного неестественно; 50–75 — частично; 0–45 — неверно.

Ответ модели проверяется перед сохранением: валидный JSON, `unit_id` из переданного каталога (чужие id отбрасываются, а их ошибки переносятся в `issues`), целевой юнит не дублируется в `others`.

### 4.2. Закрытые типы (gap, choice)

Проверяются локально по ключу. Нормализация ответа — как `norm` в прототипе: нижний регистр, `’` → `'`, схлопывание пробелов, снятие кавычек и финальной пунктуации.

```ts
type ClosedEvaluation = {
  items: { index: number; given: string | number | null; correct: boolean }[];
  correct: number;                   // сколько верно
  total: number;
};
```

Побочные юниты для gap/choice не оцениваются.

## 5. Модель данных

### 5.1. `exercises` — одно задание

| Поле | Тип | Смысл |
|---|---|---|
| `id` | bigint, identity | |
| `unit_id` | bigint, FK → `units.id` | целевой юнит |
| `type` | text | `gap` / `choice` / `rephrase` / `translate` / `free` |
| `content` | jsonb | содержимое задания по типу (раздел 3) |
| `status` | text, null | `accepted` / `failed` по последней проверенной попытке; `null`, если последняя попытка — `correct_non_target` или попыток не было |
| `target_score` | integer, null | балл целевого юнита в последней попытке: для открытых типов 0–100 из оценки (null, если конструкция не использована), для gap/choice — процент верных. Для просмотра |
| `topic` | text | тема контекста, выбранная для генерации |
| `model` | text | модель, которая генерировала задание |
| `prompt_version` | text | версия промпта генерации, например `gen-v1` |
| `created_at` | timestamptz | |
| `finished_at` | timestamptz, null | когда задание получило статус |

### 5.2. `exercise_attempts` — одна попытка

| Поле | Тип | Смысл |
|---|---|---|
| `id` | bigint, identity | |
| `exercise_id` | bigint, FK → `exercises.id` | |
| `seq` | integer | номер попытки в задании, с 1 |
| `answer` | jsonb | ответ: для открытых типов `{ "text": "..." }`, для gap — массив строк, для choice — массив индексов (`null` — пункт без ответа) |
| `evaluation` | jsonb | оценка (раздел 4) |
| `verdict` | text | для просмотра и фильтрации. Открытые типы — копия `evaluation.verdict`; gap/choice — `correct_target`, если верны все пункты, иначе `incorrect` (проставляется при локальной проверке). Рейтинг для gap/choice берёт долю верных из `evaluation`, а не `verdict` |
| `model` | text, null | модель проверки; null для локальной проверки |
| `prompt_version` | text, null | версия промпта проверки, например `grade-v1` |
| `created_at` | timestamptz | |

Уникальность `(exercise_id, seq)`.

### 5.3. Ограничения

- `type`, `status`, `verdict` — `text` + `check` со списком значений (не pg enum: новое значение — простая миграция).
- Внешние ключи `on delete restrict`: юниты не удаляются, лог тоже.
- Индекс `exercises (unit_id, created_at)` — история по юниту и чтение лога моделью ученика.
- `enable row level security` на обеих таблицах, как у `units`: читает и пишет только сервер.
- Форму `content`, `answer`, `evaluation` по типу база не проверяет: это делает валидация перед записью. В Drizzle поля типизированы через `.$type<…>()`.
- `status`, `target_score`, `finished_at` — производные от попыток. Их пересчитывает одна функция при записи попытки, в той же транзакции.

### 5.4. Модуль доступа

Серверный модуль, только на сервере:

| Функция | Что делает |
|---|---|
| `createExercise({ unitId, type, content, topic, model, promptVersion })` | новая строка, `status = null` |
| `getExercise(id)` | задание со всеми попытками по `seq` |
| `publicContent(exercise)` | содержимое без ключей (`answers`, `correct`, `reference_en`, `target_note_ru`), без `explain_ru` (объяснение пункта раскрывает ответ), без `focus` (называет грамматику) и `start_with` — только это уходит клиенту до проверки |
| `addAttempt(exerciseId, { answer, evaluation, model, promptVersion })` | в транзакции: блокирует строку задания; отказ, если задание уже `accepted` / `failed` (у gap/choice поэтому одна попытка) или вид оценки не подходит к типу; `seq = max + 1`; пересчёт `status`, `target_score`, `finished_at` |
| `listExercises({ unitId?, limit })` | история для просмотра, новые сверху |

## 6. Воркфлоу одного задания

```
 генерация ──▶ ответ ──▶ проверка ──┬── correct_target / gap-choice без ошибок ──▶ accepted (конец)
                 ▲                  ├── incorrect / gap-choice с ошибками ───────▶ failed (конец)
                 │                  └── correct_non_target ──▶ «Попробуй с нужной конструкцией»
                 └──────────────────────── новая попытка ◀──┘      или «Показать разбор» / уйти
```

1. **Генерация.** Вход: `unit_id`, `type`. Сервер берёт юнит из каталога (`unitForPrompt`: книга, раздел, номер, название, `guide`), выбирает тему из списка тем, собирает промпт генерации (раздел 7), вызывает Claude, валидирует содержимое. Создаётся строка `exercises` со `status = null`. Ключи ответов (`answers`, `correct`, `reference_en`, `target_note_ru`) клиенту до проверки не отдаются.
2. **Ответ.** Пользователь отправляет ответ, создаётся попытка `seq = N`.
3. **Проверка.**
    - gap/choice — локально по ключу: `accepted`, если все пункты верны, иначе `failed`; `target_score` — процент верных. Попытка одна.
    - открытые типы — промпт проверки (раздел 7), ответ модели валидируется и сохраняется в попытку.
4. **Ветвление по вердикту** (открытые типы):
    - `correct_target` → `accepted`, задание закончено.
    - `incorrect` → `failed`, задание закончено.
    - `correct_non_target` → статус `null`. Пользователю сообщается, что ответ верный, но без нужной конструкции, и предлагается попробовать ещё раз (раздел 8). Он может отправить новую попытку (→ шаг 2), нажать «Показать разбор» или просто перейти к другому заданию. Ни один из этих вариантов на рейтинг не влияет.
5. **Каждая попытка оценивается независимо.** Новая попытка проверяется как самостоятельный ответ на то же задание. Предыдущий ответ в промпт проверки не передаётся.

Как из оценок попыток получаются свидетельства для рейтинга — раздел 3.1 `rating-model.md`, это зона модели ученика.

## 7. Промпты

Тексты промптов — из прототипа (`genPrompt`, `gradePrompt`), со следующими изменениями. Ветку оспаривания (`opts.dispute`, поле `dispute_reply_ru`) не переносить.

**Генерация:**
- вместо однострочного описания юнита — `unitForPrompt(unit_id)`: название, раздел, номер и `guide` целиком;
- явное правило: задание тренирует только то, что описано в `guide`, и не затрагивает темы из раздела «Не входит в юнит»;
- для choice дистракторы берутся из раздела «Типичные ошибки» `guide`.

**Проверка открытых типов:**
- каталог — `catalogForPrompt(ids)` по всем юнитам книги (позже — только юниты, по которым пользователь прочёл теорию); модель ссылается на юниты по `id` из базы;
- целевой юнит передаётся с полным `guide`;
- повторная попытка проверяется так же, как первая, без предыдущего ответа.

**Разнообразие генерации** (`tasks/variety.ts`, gap, choice, rephrase, translate) — без него модель по одному юниту каждый раз берёт те же глаголы и ситуации:
- примеры из `guide` только иллюстрируют правила: их глаголы, фразы и ситуации не брать (кроме юнитов, грамматика которых привязана к конкретным словам);
- план фокуса из пунктов раздела «## Употребление» guide (есть у всех юнитов): у gap/choice — 6 пунктов по одному на предложение (пунктов больше — случайные разные, меньше — добор повторами с просьбой показать другую сторону контраста), порядок перемешан; не больше 2 предложений с одним глаголом. У rephrase и translate — один случайный пункт;
- последние 5 заданий юнита (кроме `mock`) — готовые предложения с ответом в скобках: ситуации, предложения, глаголы и ответы не повторять;
- план пишется в `content.focus`; при отбраковке пунктов gap/choice он прорежается вместе с ними.

**Правила генерации gap:** вспомогательный глагол — внутри пропуска; в вопросе подлежащее в скобках (`"___ (you / need)"` → `Do you need`); ответ нельзя угадать по соседним словам; `instructions_ru` — 1–2 предложения. Choice — те же правила, перенесённые на варианты.

**Rephrase:** без заданного начала; инструкция общая и не называет грамматику; в исходном предложении нет целевой конструкции, и выбирается такое, где она — самый естественный пересказ; один эталон.

**Translate:** 1–3 связанных естественных русских предложения (не калька с английского); контекст такой, что естественный перевод без целевой конструкции неверен или неестествен; инструкция общая и не называет грамматику; один эталон; `target_note_ru` на «ты» — в разборе строкой «Заметь» в «Как лучше», скрыт вместе с эталоном.

**Проверка открытых ответов** (`tasks/grade.ts`): каждая проблема называется один раз — то, что уже в `target`/`others`, не повторяется в `issues` (нормализация дополнительно выкидывает issues, чей фрагмент пересекается с уже названными); комментарии на «ты».

**Текущие версии:** `gap-gen-v4`, `choice-gen-v4`, `rephrase-gen-v4`, `translate-gen-v1`, `grade-v2`.

**Кэширование:** неизменная часть промпта проверки (инструкции и каталог) выносится в system prompt с prompt caching.

**Версии промптов:** у каждого промпта константа версии (`gen-v1`, `grade-v1`), которая пишется в задание или попытку. При правке промпта версия увеличивается.

## 8. Что видит пользователь

Задание открывается под строкой юнита в каталоге (кнопка ▶). Вид разбора открытого ответа — `design.md`, «Разбор открытого ответа».
- **После попытки с `correct_non_target`:** разбор скрыт — нет `summary_ru`, комментария и исправления по целевому юниту, `corrected_answer`, `natural_version`, `reference_en`, `target_note_ru`. Целевой юнит показан как «не использован», без балла. Ошибки в побочных юнитах и `issues` видны. Текст предложения формирует сервер, без примеров, на «ты» и без «!»: «Верно. А теперь напиши ответ с конструкцией из юнита N. <название>.» (`CheckResult.retryRu`). Кнопки «Показать разбор» (`reveal`, только после хотя бы одной попытки) и «Проверить».
- **После `incorrect`** задание `failed`, повтора нет — сразу полный разбор.
- **После следующей попытки** у предыдущей открывается полный разбор. Эталон показывается один, в последнем разборе.
- **Разбор:** итог (вердикт, `summary_ru`, балл целевого юнита; при `not_used` — 0), «Исправь» — все правки одним списком (целевой, побочные от худшего, `issues`), названия побочных юнитов — ссылки на их строки в каталоге; «Как лучше» — твой, исправленный, носитель, эталон. Удачные `notable` — строкой «Отлично», остальные верные побочные — одной строкой «Без ошибок: …».
- **Клавиатура:** gap — Enter к следующему пропуску (на последнем ничего), Cmd/Ctrl+Enter — проверить; choice — фокус сразу на первом предложении, цифра выбирает вариант (номера у вариантов) и переводит к следующему, Enter — дальше без выбора, Cmd/Ctrl+Enter — проверить; предложение в фокусе отмечено полосой `--speak` слева; открытые — Enter перенос строки, Cmd/Ctrl+Enter — проверить.
- **Выбор типа:** временный селект у ▶ («любой» или тип из `READY_TYPES`), запоминается в localStorage для каждого юнита (`langa:exercise-type:<id>`). Убрать — из `UnitRow.tsx` и стиль `.catalog__type`.
- Кнопки «Оспорить проверку» пока нет.
