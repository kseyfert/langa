# Тренажёр грамматики: архитектура и принятые решения

Документ для продолжения работы в новом чате. Описывает, что строим, из каких модулей, какие решения уже приняты и что осталось.

Связанные документы:
- `rating-model.md` — формулы и методика модели ученика (освоение, лестница повторений, прогресс), константы, сценарии и эталонная реализация на TypeScript.
- `claude-code-prompt.md` — промпт для Claude Code: перенос тренажёра из артефакта в self-hosted приложение.
- `grammar-drill.html` — исходник прототипа (артефакт claude.ai), эталон для логики заданий, промптов и UI.

---

## 1. Что строим

Личный тренажёр грамматики английского по книге Raymond Murphy **English Grammar in Use, 5th edition** (145 юнитов, intermediate). Пользователь — русскоязычный, уровень около B2. Продукт некоммерческий, для себя; книга куплена.

**Сценарий использования:**
- Пользователь читает теорию юнита в книге и отмечает «прочитал теорию».
- Каждый день открывает систему на **~15 минут**. Сессия ограничена **по времени**, а не по количеству заданий: задания атомарные, сессия заканчивается, когда выходит таймер.
- Система сама выбирает задания: повторяет пройденные юниты по сроку, подтягивает слабые и, если остаётся время, вводит новые.
- Теории в системе нет, только упражнения.
- Цель: пройти книгу за **~6 месяцев** так, чтобы всё хорошо запомнилось. Потом добавить другие книги и разделы.

**Расчёт** (раздел 4.5 `rating-model.md`): при ~10 заданиях в день за 5 месяцев вводится вся книга, к полугоду ~125 из 145 юнитов держатся месяц и дольше, ~89 «освоены». Поддержка после этого — 4–5 повторений в день.

**Развёртывание:** self-hosted, свой сервер, Claude API (платный отдельно от подписки). Стек по умолчанию: Next.js + TypeScript, ключ API только на сервере, вход по паролю, rate limit, Docker.

## 2. Модули

| Модуль | Отвечает за | Вход → выход | Чего не знает |
|---|---|---|---|
| **1. Каталог** | список юнитов: номер, точное название из книги, раздел, описание своими словами. Позже — новые книги и разделы | — → юниты | ничего о пользователе |
| **2. Задания** | генерация задания и его проверка, повторные попытки, оспаривание | юнит + тип → задание; задание + ответ → оценка по целевому и побочным юнитам | кто решает, его уровень, история |
| **3. Модель ученика** | всё из `rating-model.md`: оценка → свидетельства → освоение и ступень лестницы; видимый уровень, прогресс, срок повтора, «освоен» | свидетельство → новое состояние юнита; состояние + «сейчас» → уровень, прогресс, пора ли повторять | как выглядят задания, кто их генерирует, что делать с юнитом дальше |
| **4. Планировщик** | какое **следующее задание** дать: какой юнит и какой тип | состояния юнитов + отметки «в работе» / «прочитал теорию» + что уже было в этой сессии → (юнит, тип) | как задания генерируются и проверяются, формулы рейтинга |
| **5. Сессия** | таймер и цикл одного задания: спросить планировщик → задание → показать → проверить → записать в лог → обновить модель → следующее | длина сессии → цепочка заданий | ничего не решает и не считает сама |
| **Хранилище** | лог попыток (источник истины), кэш состояний юнитов, настройки: «в работе», «прочитал теорию», длина сессии, часовой пояс | — | — |

### Поток одного задания

```
Сессия ──«что дальше?»──▶ Планировщик ──читает──▶ Модель ученика (уровни, сроки)
   │                          │
   │◀──── юнит 19, перевод ───┘
   │
   ├──▶ Задания: сгенерировать ──▶ показать пользователю ──▶ ответ
   │         Задания: проверить (повторные попытки, оспаривание)
   │◀──── оценка по юнитам ───┘
   │
   ├──▶ Хранилище: записать попытку в лог
   └──▶ Модель ученика: оценка → свидетельства → новые состояния юнитов
```

Таймер вышел: текущее задание можно дорешать, следующее не запрашивается. Каждое задание засчитывается сразу; итог дня по юниту пересчитывается из всех его заданий за день, поэтому неважно, сколько было сессий.

### Границы между модулями

```ts
// 2 → 5: результат проверки
type Evaluation = {
  verdict: "correct_target" | "correct_non_target" | "incorrect";
  target: { unitId: number; status: "correct" | "error" | "partial" | "not_used"; score: number | null };
  others: { unitId: number; status: "correct" | "error" | "partial"; score: number | null; notable: boolean }[];
};

// 5 → 3: что засчитать (правила перевода — в модели ученика, rating-model.md §3.1)
type Evidence = { at: number; role: "target" | "side"; type: ExerciseType; r: number /* 0..1 */ };

// 3: состояние и чтение
type UnitState = { M: number; stage: number; dueFrom: number | null; lastSeen: number | null; day: Day | null };
function update(state: UnitState, ev: Evidence): UnitState;
function level(state: UnitState, now: number): number;
function progress(state: UnitState, now: number): number;
function isDue(state: UnitState, now: number): boolean;

// 4: следующее задание
function nextExercise(states: Map<number, UnitState>, settings: UserSettings, sessionSoFar: Attempt[], now: number): { unitId: number; type: ExerciseType } | null;
```

Модель ученика и планировщик — чистые функции без сети и базы.

## 3. Принятые решения

### Каталог
- Юниты называются **точно как в книге** и идут **в том же порядке**, с теми же разделами. Описания для LLM — своими словами, по смыслу главы.
- Каталог 5-го издания (145 юнитов, 16 разделов) уже собран, он в `grammar-drill.html` и в исходном CSV.

### Задания
- **Пять типов** по нарастанию сложности: gap (пропуск), choice (выбор), rephrase (перефразирование с заданным началом), translate (перевод с русского), free (свободный ответ). Rephrase легче translate: начало ответа подталкивает к конструкции.
- **gap и choice проверяются локально** по ключу, который LLM выдаёт при генерации (со всеми допустимыми вариантами). Их можно генерировать заранее пачками.
- **translate, rephrase, free проверяет LLM**, ответ строго в JSON, ссылки только на id юнитов из каталога.
- **«Верно, но без целевой конструкции»:** разбор скрыт (нет исправленного ответа, версии носителя, эталона, подсказок), целевой юнит показан как «не использован». Текст «Верно! А теперь напишите ответ, используя конструкцию из юнита N: …» формирует клиент, без примеров. Попыток сколько угодно, есть «Сдаться и показать разбор». Ошибки в побочных юнитах при этом видны.
- **Побочные юниты:** по умолчанию показываются только ошибки, «частично» и редкие удачные употребления (`notable`, чип «отлично»); остальное под кнопкой «Показать все найденные».
- **Оценка юнита в результате:** и число 0–100, и статус с обоснованием.
- **Оспаривание** проверки с комментарием — для всех типов. Модель пересматривает оценку и объясняет, что изменила; не должна соглашаться только из-за возражения.

### Модель ученика (подробно в `rating-model.md`)
- **Две шкалы:** освоение (Эло, 0–100, меняется после каждого задания) и ступень лестницы повторений (1, 2, 4, 7, 14, 30, 60, 120 дней).
- **Прогресс** = min(видимый уровень, потолок по ступени): пока тема не держится месяц, прогресс не выше 68. **«Освоен» = прогресс ≥ 80** — отметка для сводки и решения о новом юните, из практики не исключает.
- Освоение от времени не уменьшается; «тускнеет» только видимая полоска. За забывание отвечает лестница.
- Все задания юнита за день считаются как одна сессия. Раннее повторение идёт в освоение, но ступень не поднимает. Пропуски и выбор поднимают максимум до ступени «7 дней» и освоение до 50.
- Повторная попытка после «без целевой конструкции» — результат × 0.85 за каждую; «Сдаться» или неверный ответ без конструкции — 0.
- Ошибка в побочном юните: освоение снижается (K_SIDE), ступень −1 (не чаще раза в день), интервал заново.
- `K_TARGET = 20` (выбрано после сравнения 15–30: при 25+ «освоенных» больше не становится, а шум растёт).
- **Лог попыток — источник истины.** Состояния юнитов выводятся из него (`replay`), константы можно менять и пересчитывать всю историю.

### Платформа
- Прототип — артефакт claude.ai на подписке пользователя. Self-hosted версия — Claude API, платится отдельно (оценка: ~$0.03 за пару «генерация + проверка» на Sonnet; дешевле с кэшированием каталога в промпте, Haiku для генерации gap/choice, Batch API для заготовок).
- Защита публичного сервера: пароль из env, httpOnly-кука, rate limit.

### Порядок разработки
1. **Задания + каталог** — перенос тренажёра в Claude Code.
2. **Хранилище и лог попыток** — данные копятся с первого дня.
3. **Модель ученика** — эталонная реализация, сценарии из `rating-model.md` как тесты. Ручной режим: юнит выбирает пользователь, прогресс и сроки уже считаются.
4. **Планировщик + сессия по таймеру** — ежедневная сессия на 15 минут.

## 5. Открытые вопросы

### Планировщик (следующий шаг)
Нужно формализовать так же, как модель рейтинга:
- **Порядок приоритетов.** Черновик: (1) юниты, у которых наступил срок, самые просроченные первыми; (2) слабые юниты (низкое освоение); (3) новый юнит, если осталось время.
- **Когда брать новый юнит.** Например, не добавлять, пока среди взятых в работу освоено меньше половины. Отметка «прочитал теорию» — обязательное условие.
- **Какой тип задания давать.** По освоению и ступени: на старте gap/choice, с ростом — translate/free; на ступенях выше «7 дней» только производящие задания (иначе юнит не поднимется). Доля заданий ниже/на уровне/выше.
- **Ввод нового юнита.** Сколько заданий подряд при первом знакомстве (в расчётах — 3: gap, choice, translate).
- **Чередование.** Не давать один юнит дважды подряд, перемешивать типы.
- **Конец таймера.** Дорешать текущее задание или прервать.
