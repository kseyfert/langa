# Модуль «Каталог»: спецификация

Часть тренажёра грамматики (см. `architecture.md`). Каталог хранит юниты книг: названия, порядок, описание для генерации заданий и зависимости. Юниты сгруппированы по рабочим областям: каждый юнит принадлежит одной области, в области может быть несколько книг. Остальные модули ссылаются на юниты только по `id`.

## 1. Что входит в модуль

- Таблицы `workspaces` и `units` в Supabase Postgres: схема в Drizzle, миграция через drizzle-kit.
- Серверный модуль доступа: чтение юнитов и их представления для промптов.
- Список рабочих областей и страница области.

Не входит: интерфейс правки каталога (правка через Supabase Table Editor), прогресс пользователя — это другие модули. Отметка «в работе» (`started`) хранится в юните и меняется через `setStarted`.

Юниты и области заводятся и правятся в Supabase Table Editor; скрипта импорта нет.

## 2. Подключение

- Supabase в облаке используется как обычный Postgres: Drizzle ORM + драйвер `postgres` (postgres-js).
- Одна переменная `DATABASE_URL` — строка **session pooler** Supabase (`<region>.pooler.supabase.com:5432`). Ею пользуются и приложение, и миграции. Transaction pooler (6543) не нужен: процесс один и долгоживущий. Прямое подключение (`db.<project>.supabase.co`) доступно только по IPv6.
- Пул клиента небольшой (`max: 5`): у session pooler ограничено число соединений.
- Подключение и ключи только на сервере.

## 3. Схема

Источник истины — схема Drizzle в TypeScript. Миграция должна дать в базе следующее:

```sql
create table public.workspaces (
  id           bigint generated always as identity primary key,
  key          text      not null unique,          -- "grammar-in-use": папка content/<key>/ — промпты, evals, настройки области
  name         text      not null,                 -- "Grammar In Use"
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now()
);

create table public.units (
  id           bigint generated always as identity primary key,
  workspace_id bigint    not null references public.workspaces (id) on delete restrict,
  book         text      not null,                 -- "English Grammar in Use"
  section      text      not null,                 -- "Present and past", точно как в книге
  number       integer,                            -- номер в книге; null для своих юнитов вне книги
  position     integer   not null,                 -- порядок юнитов области, шаг 10
  title        text      not null,                 -- точно как в книге
  summary_ru   text      not null default '',      -- одна строка для интерфейса
  guide        text      not null default '',      -- markdown для промптов генерации и проверки
  article      text      not null default '',      -- markdown для человека: как произносить, видео, звук
  builds_on    bigint[]  not null default '{}',    -- id юнитов, которые желательно знать до этого
  reviewed     boolean   not null default false,   -- описание сверено с книгой
  started      boolean   not null default false,   -- взят в работу
  exclude_as_side boolean not null default false, -- не предлагать проверке как побочный
  updated_at   timestamptz not null default now(),
  unique (workspace_id, position),
  unique (workspace_id, book, number)
);

create index units_workspace_book_idx on public.units (workspace_id, book);

-- updated_at при любой правке, в том числе из Table Editor
create or replace function public.touch_updated_at() returns trigger
language plpgsql as $$ begin new.updated_at = now(); return new; end $$;

create trigger units_touch before update on public.units
for each row execute function public.touch_updated_at();
create trigger workspaces_touch before update on public.workspaces
for each row execute function public.touch_updated_at();

-- читает каталог только сервер
alter table public.workspaces enable row level security;
alter table public.units enable row level security;
```

Триггер и RLS drizzle-kit сам не генерирует: они дописываются SQL-ом в миграцию вручную. `$onUpdate` из Drizzle не годится — правки из Table Editor идут мимо приложения.

`bigint`-поля в Drizzle объявляются с `mode: "number"`, чтобы в JS приходил обычный `number`.

### Правила полей

| Поле | Правило |
|---|---|
| `workspace_id` | рабочая область юнита. Номер и позиция уникальны в пределах области; сессия и планировщик работают внутри одной области |
| `id` | выдаёт база, никогда не меняется и не переиспользуется. На него ссылаются лог попыток и состояния модели ученика. Юниты не удаляются (при необходимости можно добавить флаг архива) |
| `book`, `section` | строки, точно как в книге. Отдельных таблиц книг и разделов нет; порядок разделов выводится из `position` их юнитов |
| `number` | номер из оглавления; `(workspace_id, book, number)` уникальна. `null` — свой юнит, которого нет в книге |
| `position` | порядок внутри области, уникален в ней, шаг 10. Книга EGU5 занимает 10–1450 (`number × 10`); English Vocabulary in Use в своей области — 10–1010 так же, English Pronunciation in Use — 10–600. Свой юнит между 190 и 200 получает 195. Порядок книг в области задают позиции их юнитов |
| `title` | точно как в оглавлении, не переводится и не сокращается |
| `summary_ru` | одна строка по-русски, о чём юнит. Для списка юнитов в интерфейсе |
| `guide` | markdown, целиком уходит в промпт генерации и проверки заданий. Формат — по области, ниже «Формат guide». Пустой — юнит без заданий (`hasTasks`): он в книге для полноты, ▶ у него нет, планировщик его не предлагает, побочные ошибки его не трогают; в работе (`started`) он сразу освоен — зелёный фон, карта, счётчики |
| `article` | markdown для человека: как произносить, видео артикуляции, звук, пары слов. Статья — для человека, `guide` — для промптов: в промпты статья не идёт и на `hasTasks` не влияет (юнит только со статьёй — без заданий). Пустая — статьи нет. Встраивания и показ — ниже «Статья юнита» |
| `builds_on` | id юнитов (любой книги той же области), которые желательно знать до этого. Только прямые зависимости, обычно 0–3 |
| `reviewed` | `true`, когда описание сверено с книгой |
| `exclude_as_side` | `true` — юнит-обобщение (например, на различение юнитов 1–6): в каталог проверки не идёт, побочным в оценке не бывает — его ошибки должны лечь на частные юниты. Целевым юнит быть может. Действует только на новые проверки, история не пересчитывается |


### Рабочие области

| `key` | область | книга | `guide` |
|---|---|---|---|
| `grammar-in-use` | Grammar In Use | English Grammar in Use, 5th edition (145 юнитов) | грамматика: «## Формы» |
| `vocabulary-in-use` | Vocabulary In Use | English Vocabulary in Use, Upper-intermediate | лексика: «## Лексика» |
| `pronunciation-in-use` | Pronunciation In Use | English Pronunciation in Use, Intermediate, 2nd edition (60 юнитов, без раздела E) | формат появится с заданиями |

Правила генерации и проверки области — `content/<key>/README.md`.

### Формат guide

Разделы второго уровня, в таком порядке; одинаковы у грамматики и лексики, кроме второго (у произношения формат появится с заданиями):

| раздел | что внутри |
|---|---|
| `## Фокус` | одним абзацем — чему учит юнит |
| `## Формы` (грамматика) | формы и правила конструкций юнита |
| `## Лексика` (лексика) | слова и выражения юнита группами, `- группа: слово, слово (разг.)`; пометки регистра — `разг.` / `письм.`, британское / американское — `брит.` / `амер.`. Это целевая «конструкция» заданий области |
| `## Употребление` | пункты `- …`, по пункту на употребление; у лексики — слова пункта и после тире типичные ситуации (`- хитрость: cunning, crafty, sly — соперник, персонаж, торговец`). Из пунктов строится план фокуса заданий (`exercise-spec.md` §7); пунктов не меньше 6, иначе — предупреждение при старте |
| `## Типичные ошибки` | пункты: ошибки русскоязычного ученика; у лексики — ложные друзья, кальки, не та коллокация, не тот регистр. Из них — дистракторы choice и ловушки translate |
| `## Не входит в юнит` | пункты: соседние темы с номерами юнитов, где они разбираются; генерация их не трогает |

## 4. Типы и модуль доступа

```ts
/** key — папка content/<key>/ (architecture.md, «Содержимое области»). */
export type Workspace = { id: number; key: string; name: string };

export type Unit = {
  id: number;
  workspaceId: number;
  book: string;
  section: string;
  number: number | null;
  position: number;
  title: string;
  summaryRu: string;
  guide: string;
  article: string;
  buildsOn: number[];
  reviewed: boolean;
  started: boolean;
  excludeAsSide: boolean;
  updatedAt: string;
};
```

Серверный модуль `catalog` (только на сервере):

| Функция | Что делает |
|---|---|
| `listWorkspaces()` | рабочие области по `id` |
| `getWorkspace(id)` | область или `null` |
| `listUnits(workspaceId, book?)` | юниты области в порядке `position` |
| `setStarted(id, started)` | взять юнит в работу или снять отметку |
| `getUnit(id)` | юнит или ошибка «не найден» |
| `getUnits(ids)` | несколько юнитов по id, в порядке `position` |
| `catalogForPrompt(ids)` | компактный список `id. title` для промпта проверки — только переданные юниты, в порядке `position` |

`catalogForPrompt` принимает список id, а не книгу. Отметка «прочитал теорию» — это `started` (взят в работу), но каталог проверки по ней не сужается: передаются все юниты той же книги той же области, кроме `exclude_as_side`.

## 5. Страницы каталога

Просмотр, без правки. Вид — по `design.md`. `/` перенаправляет на `/catalog`.

`/catalog` — список рабочих областей: заголовок «Каталог», строки через линейку — название (вес 550) и справа `.mono --t-xs` «юнитов N · в работе N · освоено N» (статусы — как на карте юнитов). Строка целиком ведёт в область. Пустой список: «Рабочих областей пока нет. Заведи первую в Supabase Table Editor: таблица workspaces.»

`/workspace/<id>` — одна область; несуществующий id — 404. Пункт «Каталог» в шапке подсвечен и здесь.

- Заголовок — название области, под ним строка `.muted .mono`: сколько юнитов, разделов, книг. Ниже плеер сессии (задания только из этой области) и карта юнитов.
- Группировка в порядке `position`: книга (`--t-lg`) → раздел (капитель) → строки через линейку. Группа — подряд идущие юниты: юнит другой книги разрывает книгу, и её заголовок появляется снова.
- Строка: номер (`.mono`), название (вес 550) и сразу за ним ▶ «Задание» и временный селект типа. При наведении на строку вместо номера — галочка «В работе» (`setStarted`); строка юнита в работе на фоне `--learning-bg`, освоенного — `--mastery-bg`. Ниже названия — `summary_ru` (`.muted --t-xs`). У правого края — показатели юнита (`design.md`, «Показатели юнита в строке»): график рейтинга за 4 недели (точка на конец каждого дня, последняя — на момент загрузки), интервал в днях и полоса освоения. Без практики — пусто. У юнита не в работе показатели есть, только если он практиковался, и видны лишь в раскрытой строке, бледно.
- Клик по названию раскрывает строку: `builds_on` ссылками на строки юнитов (`#unit-<id>`, переход с подсветкой) статья (`article`, «Статья юнита») и `guide`, оба отрендерены на сервере (`marked`). Нет ни статьи, ни `guide` — «Описания пока нет»; у юнита только со статьёй этой строки нет.
- Задание открывается под строкой, закрывается крестиком. После проверки страница перечитывается с сервера (`router.refresh`) — показатели обновляются.
- Пустая область: «Юнитов пока нет. Добавь их в Supabase Table Editor: таблица units, workspace_id = N.»

### Статья юнита

`renderArticle` (`src/server/catalog/article.ts`, чистая функция, на сервере) превращает `article` в HTML, `Article.tsx` его показывает. Пока статья видна только в раскрытой строке каталога (разминка в сессии — позже).

- Ссылка, стоящая одна в своём абзаце (голый URL или `[подпись](URL)`), заменяется встроенным элементом, если адрес из белого списка (`EMBED_HOSTS` — одна константа); иначе остаётся ссылкой. Ссылка внутри текста или пункта списка — всегда ссылка.
  - YouTube — `youtube.com/watch?v=…` (`www.`, `m.`) и `youtu.be/…`, с `t` (`90`, `90s`, `1m30s`) или `start` → iframe `youtube-nocookie.com/embed/<id>?start=N`, `loading=lazy`, 16:9 по ширине статьи; подпись ссылки — `title` iframe.
  - Звук — `.mp3`, `.ogg`, `.oga`, `.wav` с `upload.wikimedia.org` → `<audio controls preload=none>`, подпись — текст ссылки (у голого URL подписи нет).
  - YouGlish — `youglish.com/pronounce/<слово>/english[/<акцент>]`, акцент из `us uk aus ca ie sco nz`. Абзац только из таких ссылок (голые URL или `[подпись](URL)`), разделённых пробелами, запятыми или « · », — один виджет со списком слов в порядке ссылок (одна ссылка — список из одного); подпись — текст ссылки, у голого URL — слово из адреса; акцент у каждого пункта свой. Что-то ещё в абзаце или хоть одна ссылка мимо белого списка — абзац остаётся текстом со ссылками. На сервере — место виджета `.article__yg` («Загружаю…»), список — в `data-yg-items`. Когда место становится видно (строка раскрыта; `IntersectionObserver`), грузится `youglish.com/public/emb/widget.js` (один раз на страницу), и на этом месте встаёт виджет: `widget.fetch(слово, 'english', акцент)` первого пункта, переключатель слов в шапке делает `fetch` выбранного, от их интерфейса — только видео (`components: '0'` строкой: число 0 widget.js подменяет на 255, весь их интерфейс). Субтитр (`onCaptionChange`, приходит URL-кодированным, слово в `[[[…]]]`; `onFetchDone` — «Примеров не нашлось»), переключатель слов, ‹ › ↻ и скорость 0.75 / 1 — наши; iframe обрезан по плееру, их реклама и «powered by» за краем (`design.md`, «Статья юнита»). Пока место не видно, от YouGlish не грузится ничего: каждый виджет тратит поиск из их дневной квоты, а свёрнутых статей на странице десятки.
- Сырой HTML в статье не исполняется — показывается текстом; ссылки не `http(s)`/`mailto`/относительные — только текстом.

## 6. Подключение к модулю заданий

- Генерация и проверка берут юнит через `getUnit` и описывают его в промпте сами — книга, раздел, номер, название, `guide` (юнитов с пустым `guide` здесь не бывает — заданий по ним нет) — вместо прежней однострочной `desc`. Текст описания — в md-файлах промптов типа (`exercise-spec.md` §7).
- Проверка получает каталог через `catalogForPrompt(ids)`; модель в ответе ссылается на эти `id`.
- В прототипе (`reference/grammar-drill.html`) юниты идентифицировались номером в книге. Совпадение `id` и `number` не предполагать.

## 7. Шаги и критерии готовности

1. **Каркас** — Next.js + TypeScript, стили и шрифты по `design.md`, Drizzle, `.env.example`. Готово: `npm run dev` поднимает приложение.
2. **Миграция** — таблица, триггер, RLS. Готово: таблица видна в Supabase.
3. **Модуль доступа.** Готово: функции из раздела 4 работают на базе.
4. **Страницы каталога.** Готово: `/catalog` показывает области, `/workspace/<id>` — юниты области (или пустое состояние).
