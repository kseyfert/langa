# Задача: перенести тренажёр грамматики из артефакта Claude в self-hosted веб-приложение

## Контекст

В корне проекта лежит файл `reference/grammar-drill.html`. Это рабочий прототип, сделанный как артефакт claude.ai: тренажёр по 145 юнитам книги Raymond Murphy «English Grammar in Use», 5th edition. Задания генерирует и проверяет Claude. В артефакте запросы к Claude шли через `window.claude.use("sample")` / `sample.json(...)` на подписке пользователя. В self-hosted версии их нужно заменить на Claude API через свой бэкенд.

Прочитай `reference/grammar-drill.html` целиком, прежде чем что-то делать. Это источник истины для логики, промптов, каталога юнитов и состава экрана. Внешний вид — не из эталона, а строго по `specs/design.md` (см. «Стек»).

**Перенеси только то, что есть в эталоне, кроме прогресса.** В эталоне уже есть чекбоксы «Беру в работу», фильтр «Все / В работе», баллы освоения, прогресс-бары, блок «Прогресс» с дельтами и сохранение через `claude.use("db")`. Всё это сейчас НЕ переносим, это будет следующий этап. Убери также код score-модели (`DIFF`, `applyScore`, `applyGrade`, `revert`, `deltaBlock`, `save`, `prog`, `entry`).

## Стек

- TypeScript везде.
- Next.js (App Router): страница плюс route handlers для API. Один процесс, один деплой.
- `@anthropic-ai/sdk` на сервере. API-ключ только в переменной окружения `ANTHROPIC_API_KEY`, в браузер он не попадает никогда.
- Без UI-фреймворков и CSS-библиотек. Стили эталона **не переносим**: внешний вид строго по `specs/design.md` — его токены, шрифты Inter Tight и JetBrains Mono из npm (`@fontsource-variable/*`, не Google Fonts), компоненты, тёмная тема через `prefers-color-scheme`, тон текстов. Компонент — `Component.tsx` + `Component.css` рядом, классы `block__elem--mod`. Адаптив под телефон сохраняется.

## Что перенести 1:1

1. **Каталог юнитов** — не из массивов эталона, а из таблицы `units` в Supabase по `specs/catalog-spec.md`. До переноса должны быть готовы миграция, модуль доступа и импорт `data/egu5-units.csv`. Описания из `UNITS` эталона (третий элемент) идут в начальный `summary_ru`. Юниты везде идентифицируются `id` из базы, а не номером в книге (§6 спецификации); номер — только для показа.
2. **Пять типов заданий**: gap, choice, translate, rephrase, free. Генерация через промпт `genPrompt`, тексты промптов перенести дословно. Случайная тема из `TOPICS` и random seed тоже сохраняются. Описание юнита в промпте — `unitForPrompt(id)`: пока `guide` пуст, в нём `summary_ru`.
3. **Проверка gap и choice — локально**, без API: функции `norm`, `checkClosed`, `paintClosed`, валидация `normalizeEx`. Оспаривание закрытых заданий идёт через API (промпт внутри `paintClosed`).
4. **Проверка translate / rephrase / free — через API**: `gradePrompt` и `GRADE_SHAPE` дословно, включая ветки retry и dispute.
5. **Сценарий «Верно, но без целевой конструкции»** (`renderAttempts`, переменная `concealed`):
    - пока не сделана следующая попытка, скрыты summary, комментарий к целевому юниту, исправленный ответ, версия носителя, эталон и `target_note_ru`;
    - целевой юнит показан как «не использован», без балла;
    - текст предложения переписать формирует клиент, а не модель: «Верно! А теперь напишите ответ, используя конструкцию из юнита N: <название>.»;
    - попыток сколько угодно, есть кнопка «Сдаться и показать разбор».
6. **Побочные юниты**: по умолчанию видны только `error`, `partial` и `correct` с `notable: true` (чип «отлично»). Остальные под кнопкой «Показать все найденные (N без ошибок)».
7. **Оспаривание** с комментарием (`disputeBlock`) для всех типов: модель пересматривает оценку и возвращает `dispute_reply_ru`.
8. **Встроенный пример** (`EXAMPLE`, gap на юнит 7): показывается при первом открытии и работает без API. Юнит 7 находится через `findByNumber`.
9. В `localStorage` по-прежнему запоминаются только выбранный юнит и тип задания.

## Бэкенд

- `POST /api/generate` — `{ unitId, type }` → JSON задания. Промпт собирается на сервере.
- `POST /api/grade` — `{ exercise, answer, retry?, dispute? }` → JSON оценки.
- `POST /api/dispute-closed` — для оспаривания gap и choice.
- Промпты собираются только на сервере, клиент присылает данные, а не текст промпта.
- Разбор ответа модели устойчивый, как у `sample.json`: весь ответ как JSON, иначе тело code fence, иначе от первой `{`/`[` до последней `}`/`]`. Если не распарсилось, возвращать понятную ошибку, клиент показывает «Claude ответил в неожиданном формате. Попробуйте ещё раз.».
- Модель задаётся через env: `CLAUDE_MODEL_GENERATE` и `CLAUDE_MODEL_GRADE`, по умолчанию `claude-sonnet-5-5` для обоих. Перед тем как зашить ID моделей, сверься с актуальной документацией Anthropic.
- **Prompt caching**: каталог (`catalogForPrompt`, пока — все юниты книги) и инструкции проверки одинаковы в каждом запросе. Вынеси их в system prompt с `cache_control`, а в user-сообщение — только конкретное задание и ответ.
- Ошибки API (rate limit, перегрузка, 5xx) переводить в понятные русские сообщения, как `ERR_RU` в эталоне.

## Доступ

Аутентификации, пароля и rate limit нет: личный инструмент, один пользователь (см. `specs/architecture.md`, «Платформа»).

## Деплой

- Без Docker: `npm run build` и `npm start` на сервере.
- `.env.example` со всеми переменными.
- `README.md`: локальный запуск, переменные окружения, сборка и запуск на сервере.

## Проверка

- Юнит-тесты (Vitest) на `norm`, разбор JSON из ответа модели и `normalizeEx`.
- Прогони сборку и тесты. Подними приложение локально и проверь, что страница открывается и пример с пропусками решается без API-ключа.
- Если ключ доступен, сделай по одному реальному запросу генерации и проверки и покажи результат. Если нет, так и скажи.
