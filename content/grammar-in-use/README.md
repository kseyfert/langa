# Grammar In Use — правила области

Содержимое области `grammar-in-use` (Raymond Murphy, *English Grammar in Use*, 5th edition): промпты типов, evals и судьи, настройки (`workspace.yaml`). Здесь — правила, которые относятся только к грамматике этой книги; общее устройство типов и промптов — `specs/exercise-spec.md` (§4, §7) и `specs/exercise-types.md`. Тексты правил живут в md-промптах; этот файл описывает, что в них и почему.

## Ключ закрытых типов (gap, choice)

Ключ британский (книга Murphy). Сокращения при сравнении не раскрываются (`norm`, exercise-spec §4.2): ученик вводит полные формы (`has not`, `do not`, `will`), поэтому в ключе gap полная форма обязательна, сокращённая — по желанию.

**Правила генерации gap** (ключ — выше):
1. **Один ответ по юниту.** Верный ответ — тот, которого требуют правила целевого юнита (`guide`) в этом контексте. Контекст оставляет ровно один ответ по правилам юнита; если подходит и другая конструкция того же юнита — лучше переделать контекст, иначе добавить её в `answers`. Ответов вне юнита в `answers` нет, даже если это верный английский.
2. **Полные формы.** У каждого принятого ответа в `answers` есть полная форма, в том числе в переспросах и инверсии (`Did she not`, `Have you not`); ученик вводит только полные формы, сокращения при сравнении не раскрываются, поэтому сокращённые можно не перечислять.
3. **Ключ британский**, по книге. Известное расхождение с американским вариантом коротко отмечается в `explain_ru`.
4. **Нет ошибок юнита в ключе.** В `answers` нет ответов, которые юнит считает ошибкой в этом контексте (после уже совершённого действия — только `need not have hurried`, не `did not need to hurry`).
5. **В скобках — только выбор вне юнита.** Подсказывается только выбор, которому юнит не учит (модальный глагол, время, отрицание, устойчивое выражение). Слово, выбор которого — предмет юнита (по его `guide`), в скобках не стоит: в юните must и can't `can't` — решение ученика, а не подсказка. После всех подсказок у ученика остаётся решение, которому учит юнит; если не остаётся — пункт переделывается. Базовая форма слова, которое ученик ставит в пропуск (обычно глагола), в скобках есть всегда, даже если это слово юнита (`___ (I / need) a referral?` → `Do I need` в юните про need): не подсказываются только форма и конструкция, выбору которых учит юнит. Без скобок — только пропуск, который сам есть выбор слова (правило 7).
6. **Скобки — базовые формы.** Совпадение ответа с базовой формой (present simple, глагол после модального) — нормально. В юнитах на порядок слов слова в скобках даются не в порядке ответа (например, в порядке прямого вопроса), иначе ответ просто переписывается.
7. **Выбор слова — в пропуске.** Если пункт фокуса — выбор слова (when / if, союз, предлог), это слово стоит в пропуске, а не в тексте. Если пункт фокуса нельзя проверить пропуском (например, пунктуация), пункт проверяет его грамматическую сторону.

Кроме того: вспомогательный глагол — внутри пропуска; в вопросе подлежащее в скобках (`"___ (you / need)"` → `Do you need`); ответ нельзя угадать по соседним словам; `instructions_ru` — 1–2 предложения.

**Правила генерации choice** (ключ — выше):
1. **Один верный вариант по юниту.** Верный — тот, которого требуют правила целевого юнита (`guide`) в этом контексте. Контекст исключает каждый дистрактор по правилам юнита; если дистрактор тоже допустим по смыслу или по правилам юнита — переделывается контекст или дистрактор. Верный дистрактор засчитывает ученику ошибку за правильный ответ.
2. **Правдоподобные дистракторы.** Дистракторы — формы, которые ученик этого юнита правдоподобно выберет: типичные ошибки из раздела «Типичные ошибки» `guide` или неверный выбор между конструкциями юнита. Неграмматичная форма — только если это типичная ошибка учащихся (`must to`, `needn't to`); заведомая бессмыслица (`am must`, `will can call`) выдаёт верный ответ.
3. **Отличие — только выбор юнита.** Дистрактор не вносит ошибок другого юнита: артикль, согласование, порядок слов в вопросе, время в юните на порядок наречий.
4. **Текст сходится с каждым вариантом.** Всё, что меняется между вариантами, — внутри пропуска (не `___ I.` с вариантом `So I am`).
5. **Ключ британский**, по книге. Известное расхождение с американским вариантом коротко отмечается в `explain_ru`.
6. **Выбор слова — в вариантах.** Если пункт фокуса — выбор слова (when / if, союз, предлог), это слово стоит в вариантах, а не в тексте. Варианты могут различаться пунктуацией, если юнит её учит (точка или вопросительный знак после косвенного вопроса в юните 50).

Кроме того: 2–3 варианта; вспомогательный глагол — внутри каждого варианта; в вопросе подлежащее — в вариантах; верный вариант нельзя угадать по соседним словам; позиция верного варианта меняется.

## Открытые типы: генерация

**Rephrase:** без заданного начала; инструкция общая и не называет грамматику; в исходном предложении нет целевой конструкции, и выбирается такое, где она — самый естественный пересказ; один эталон.

**Translate:** 1–3 связанных естественных русских предложения (не калька с английского); контекст такой, что естественный перевод без целевой конструкции неверен или неестествен; инструкция общая и не называет грамматику; один эталон; `target_note_ru` на «ты» — в разборе строкой «Заметь» в «Как лучше», скрыт вместе с эталоном.

**Free:** короткая (1–2 предложения) личная ситуация или вопрос, только по-английски (`prompt_en`), простым ясным языком; естественный ответ носителя — с целевой конструкцией; не перечислять, что должно быть в ответе, и не давать примеров содержания; в вопросе целевой конструкции нет, если есть другая естественная формулировка; инструкции (длина, язык) внутри вопроса не повторяются; один пример ответа, сам в рамках объёма.

## Проверка открытых ответов

Правила оценки (`grade-system.md`, у каждого типа своя копия; подробно — exercise-spec §4.1): общие для трёх типов: правильность — по правилам целевого юнита и английскому, а не по эталону; каждая ошибка — ровно одному, самому частному юниту, один фрагмент на два юнита не записывается; ошибка в целевой конструкции — только в `target_unit`, не в `other_units`; целевая конструкция с ошибкой и без верного употребления — `error` с баллом ниже 50, `partial` — только когда часть употреблений верна, а часть нет; только у rephrase — ещё «не использована — `not_used` и `score: null`» и шкала `error` < 50, `partial` 50–75 и для `other_units`. Описание задания в `grade-user.md` не требует целевой конструкции: обход — законная ветка `correct_non_target`, её решает сервер по `not_used` (у rephrase «using the target structure» убрано, у translate и free его не было).

Только у rephrase: целевая конструкция не использована вовсе (в том числе при грамотном обходе) — `not_used` и `score: null`, `partial` и `error` бывают только у использованной конструкции; шкала «`error` — ниже 50, `partial` — 50–75» одна для целевого юнита и для `others`. У translate и free этих правил нет: в translate шкала для `others` давала ложную побочную ошибку (`I've rented` под юнитом 7 во всех повторах) и ослабляла провал целевого юнита.

## Версии

**Текущие версии.** Генерация — `gap-gen-v8`, `choice-gen-v6`, `rephrase-gen-v5`, `translate-gen-v2`, `free-gen-v2`; проверка — `rephrase-grade-v6`, `translate-grade-v6`, `free-grade-v6`.

**История проверки.** До v4 у трёх типов была общая `grade-v3`; с v4 у каждого типа своя версия, выбранная по evals. Правки v5 (шкала «`error` ниже 50, `partial` 50–75» и для `others`, `not_used` при неиспользованной конструкции, без «using the target structure» в `grade-user.md`) приняты только у rephrase: в translate шкала для `others` давала ложную побочную ошибку и ослабляла провал целевого юнита, поэтому translate и free остались на v4, а имена `translate-grade-v5` и `free-grade-v5` заняты отвергнутой правкой и не используются. Затем переход на схему ответа (structured outputs) поднял версии всем вызовам — проверке до v6, генерации до текущих выше: менялся только способ задать формат, текст правил тот же.
